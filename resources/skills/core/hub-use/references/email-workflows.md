# Email workflows

## Proactive evidence search

Automatically search email when it is a likely primary evidence source for
research, review, reconciliation, memory reconstruction, prior decisions or
promises, receipts and orders, bookings and travel, job applications, account
administration, supplier work, or recent correspondence. Do not search when the
user forbids it or email is clearly irrelevant.

Keep discovery bounded and read-only. Start with the one to three accounts most
strongly suggested by the person, domain, project, or address. Search envelope
metadata with a narrow sender, recipient, subject, date, reference, or keyword
window; read only likely matches and widen only when necessary. State briefly
when email materially informed the result without exposing unrelated content.

## Routing and safety

Prefer configured Hub mail tools, then Himalaya when selected and working.
University mail may require Apple Mail on macOS or Outlook/webmail on Windows.
Use a native or web surface when exact rich signatures or embedded images
matter. Before GUI use, load `computer-use`; keep fallbacks nonfrontmost unless
the user must interact.

Email discovery authorizes no mailbox mutation. Never send, forward, delete,
archive, move, mark, flag, label, upload, or otherwise mutate without the
specific approval required by the core skill. A saved draft does not leave the
mailbox and may be created without send approval; state where it was saved.

Inspect attachment metadata first and download only a clearly relevant file
needed for the task. Himalaya does not add native signatures automatically;
use only a verified signature or choose the native/web route when fidelity
matters. Never invent an address, signature, attachment state, or delivery.
